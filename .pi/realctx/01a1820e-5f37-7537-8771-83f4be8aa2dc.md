MSYS `exec` breaks the Windows parent-process chain, so `taskkill /T /PID <root>` leaves the task's command and background children running (orphans pile up). realtasks `killGroup(pid, sig, sync, taskId)` on Windows runs a bash-builtins-only scan of `/proc/*/environ` for `PI_TASK_ID=<id>` (~100 ms), reads `/proc/<pid>/winpid`, then one `taskkill /F /T` for the root plus all matches, then scans and kills a second time. It always forces: a non-forced taskkill can end the root (MSYS maps it to a signal) and orphan the children. To find leaked task processes by hand, scan `/proc/*/environ` for any `PI_TASK_ID=` from Git Bash. PID start time on Windows comes from PowerShell `(Get-Process -Id N).StartTime.ToFileTimeUtc()` (~300 ms, so it is fetched async after spawn).
