In realtasks, `bash`'s `timeout` (seconds) is the foreground window, as in Claude Code: default `defaultTimeoutMs` 120000, clamped to `maxTimeoutMs` 600000 (config in realtasks/config.json). A command still running at the end is promoted to a background task and never killed; `timeout` is ignored with `run_in_background`. The old `yield_ms` param, `yieldMs` config and `steerPromotes` (typing promotes) were removed; typed messages just queue in Pi. Only monitor `timeout_ms` produces status `timed_out`. The "ctrl+shift+b to background · auto in 1m48s" hint is rendered inside the bash row from `details.hint` on partial results (wrapped `builtin.renderResult`), not as an editor widget; the key is shown only when `rt.backgroundKey` was set by `registerShortcuts`.
