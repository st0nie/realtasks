realtasks reads config from `<agentDir>/realtasks/config.json` (default `~/.pi/agent/realtasks/config.json`), with an optional override in `.pi/realtasks/config.json` that applies only when `ctx.isProjectTrusted()` is true. Pi's `settings.json` (`tasks` key) is no longer read. Config is loaded at `session_start`; trusted project overrides are surfaced in row descriptions but never modified by the UI.

`/tasks settings` (`src/settings.ts`) opens `SettingsPanel` via `ctx.ui.custom` (`SettingsList` + `ChoiceSubmenu` with `SelectList` presets and `Input` custom entry; `Input.setValue()` leaves the cursor at 0, so send End `\x1b[F` after `setValue` to place the cursor at the end). Edits write only `<agentDir>/realtasks/config.json` atomically via `writeConfigFile()` after `pruneDefaults()` (dropping keys equal to `DEFAULTS` while keeping unknown keys and `dir`) and immediately call `rt.loadConfig()` so changes apply without `/reload`; shortcut changes notify on close that `/reload` is required. Invalid JSON in the user file blocks opening/saving so broken files are never overwritten. Other invalid/non-object configs produce one warning (`ctx.ui.notify`, or stderr in print mode) and are ignored.

Tests set `PI_CODING_AGENT_DIR` to a temp dir via `writeUserConfig()` in `test/helpers.ts`. For live smoke tests, `--provider uniontech-ai --model deepseek-v4.1-flash` works when the cliproxyapi models fail with TLS/WebSocket errors.
