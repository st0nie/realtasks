In realtasks (`src/proc.ts`), MSYS/Cygwin programs (Git Bash) fail every write to the append-only handle libuv creates for `O_APPEND` (even `a+`): the command exits 1 with no output. Fix used: on Windows Node opens the log without `O_APPEND`, and the wrapper (`WRAPPER_WIN`) starts with `exec >>"$PI_TASK_LOG" 2>&1` (or `2>>"$PI_TASK_ERR"`), then runs the command with `"$BASH" -c` (MSYS→MSYS spawn keeps O_APPEND across rotation; going through Git's native `bin\bash.exe` launcher loses it and leaves NUL gaps after rotation). Native (non-MSYS) writers still leave NUL runs after a rotation; `Task.poll` strips NULs. The wrapper is passed via env `PI_TASK_WRAPPER` with argv `-c 'eval "$PI_TASK_WRAPPER"'` because node-pty's Windows argv quoting garbles nested double quotes for MSYS bash.
