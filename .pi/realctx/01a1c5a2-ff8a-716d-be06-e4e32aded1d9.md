To prevent multiple completed tasks from being steered one-by-one across separate LLM turns (due to Pi's default `steeringMode: "one-at-a-time"` on `agent.steeringQueue`), `Notifier` in `src/notify.ts` holds `wake` items in `this.held` whenever `isBusy()` is true instead of calling `pi.sendMessage(..., { deliverAs: "steer" })` on a 300ms timer.

At the turn boundary (`turn_end` and `agent_before_settle` in `index.ts`), `takeForSettle()` deduplicates held and pending `wake` items against `isNotified(id)` (dropping any task already read in the same turn via `task_output` or `task_wait`), latches and toasts the remaining items, and returns one combined `custom_message` (`customType: "task-notification"`) with `continue: true`. If a run is aborted (`outcome === "aborted"`), `turn_end` skips consuming held wake items and `agent_settled` flushes them once idle.

When idle (`isBusy() === false`), `Notifier.queue()` uses adaptive coalescing via `TaskManager.hasRunningWake()`: it widens the timer to `IDLE_RUNNING_COALESCE_MS` (1200ms) while sibling `wake` shell tasks are still running, and shortens it back to `COALESCE_MS` (300ms) as soon as the last running `wake` shell task finishes.
